## Latest implementation slice

- Controller input hardening (2026-10-12): left- and right-stick axes now use the same finite-checked dead-zone and full-range rescaling helper, and keyboard/controller rotation is bounded to the intended -1..+1 range. Invalid axis readings are ignored instead of contaminating the flight vector; regression tests cover stick drift, symmetry, over-range values, NaN/infinity, and mixed keyboard/controller inputs. This is automated input-state coverage only; gamepad feel still needs a real controller session on Windows.

- Collision arbitration test extraction (2026-10-12): the first-contact comparator now lives in a small raylib-free helper instead of being hidden inside the game loop. Unit tests cover earlier contacts, ignored later contacts, stable tie ordering, absent candidates and non-finite fractions. This isolates the ordering rule so future collision changes can be checked without launching the renderer; manual gameplay and hardware verification are still separate acceptance steps.

- Unified first-contact ordering (2026-10-12): tunnel walls, curved gate throats, missed gate planes and moving mines are compared by movement fraction before a run ends. The craft and run clock now stop at the earliest contact, rather than whichever collision check ran first. Clean gates passed before the impact still count; a gate reached at the same moment as a crash does not. A deterministic test checks the leading-edge mine-contact point. Automated checks can validate the code path, but real gameplay handling still needs a Windows hardware review.

- Gate-plane crash positioning (2026-10-12): a missed aperture now freezes the craft and run clock at the interpolated gate-plane crossing, rather than showing the ship at the end of the frame after it had already crossed the gate. The crossing fraction is shared with the same point used for gate collision and scoring; invalid crossings fail closed at the last known-good state. A regression assertion checks the expected half-frame crossing. Windows/Linux CI can validate the code path, but in-game visuals still require a manual run.

- First-contact ordering for wall and gate-throat impacts (2026-10-12): both collision paths now report contact fractions. The game chooses whichever impact happens first, freezes the flight state at that location/time, and records the correct gate index for a sleeve crash. This avoids letting the order of collision checks mislabel a same-frame impact. Regression coverage checks exact side contact inside a generated throat; automated Windows and Linux checks are rerunning after this slice.

- Swept tunnel-wall contact (2026-10-12): wall checks now sample the full movement segment against the generated tunnel radius and refine the first safe/hit interval to locate contact. A crash result stops at that contact point instead of the rendered frame's endpoint, so a narrow section cannot be skipped between frames and the run record does not include travel after impact. Automated tests cover a direct crossing, a clear segment, and a generated radius pinch with safe endpoints. Manual handling and frame-rate checks on Windows hardware are still required.

- Course continuity gate (2026-10-12): `validateCourse` now measures the per-course-unit rate of centerline, radius and twist changes and rejects samples exceeding generous continuity bounds. The metrics are exposed in `CourseValidation` and covered across the existing deterministic seed regression set. This is a generation-time validation improvement, not a claim that every camera or collision behavior has been manually verified in-game. The viewport tests also now cover portrait-window letterboxing and clicks in ultrawide bars.

- Tunnel-frame continuity regression (2026-10-12): added an adjacent-frame sweep across 12 derived seeds and 257 stations per seed (3,072 neighbouring frame intervals) to catch abrupt tangent/right/up orientation changes. The same regression slice tests hazard-centre evaluation with an extreme finite clock value and asserts that the resulting position remains finite.

- Game UI/content pass (2026-10-11): replaced the static ellipse backdrop with a moving 3D procedural tunnel and seeded gate silhouettes, rebuilt the main menu as a command deck plus live ship hologram/telemetry, added animated angular controls, textured panels and screen-specific materials, and kept the real flight scene visible beneath pause and nested dialogs. The portable pack now generates 12 original 4096 × 2048 RGB material sheets (288 MiB of raw pixels); the UI streams one sheet per screen and unloads it on transitions. The source checkout still works without baked assets. The in-flight interface now separates flight data, gate approach, threat monitoring, run records, and optional FPS/frame-time telemetry; the Controls screen has matching keyboard and gamepad keycaps and clearer input groups. The latest Windows x64 CI package completed build and unit tests at 225.9 MiB compressed; this remains a development artifact, not a public release.

- Collision frame fix (2026-10-11): gate-throat sweeps, exact gate-plane crossings, mine contact and pickup contact now interpolate FlightState X/Y as cross-section-local offsets. They no longer apply a second centerline shift during collision checks. Seeded layouts, tunnel geometry and the existing ship models are unchanged; regression assertions cover curved-course crossings and near-edge gate contact.
- Predictive mine cue (2026-10-11): inside the urgent threat window, the HUD samples the deterministic mine trajectory at the player's estimated arrival time and reports the predicted lane offset plus overlap at the mine plane. It labels the assumption (hold current lane) rather than pretending future steering is known. The nearest-mine selection now keeps the just-passed mine active through its rear collision margin, preventing the warning from jumping to a distant mine at the exact centre plane. Tests cover predicted motion, overlap boundaries, invalid timing and the rear-warning handoff.

- The flight HUD now labels the next gate CLEAR, PREPARE, APPROACH, or IMMINENT using estimated arrival time from actual forward speed, then shows both distance and seconds. The thresholds automatically respond to braking, acceleration, boost and dash; this gives the player a timing cue while far tunnel geometry is hidden by the visibility horizon. Pure-helper tests cover stage boundaries, speed changes, a gate already crossed, invalid input, and urgency ordering.

- FPP's eye now sits forward and slightly above the ship origin inside the canopy. A centered tunnel-frame reticle returns in stable FPP. Camera roll blends out across the FPP-to-TPP transition, and the spacecraft fades in only after the chase camera clears its hull. If a tight sleeve forces the camera close to the ship, model visibility also fades by actual camera-to-ship distance. The HUD reports actual units/second after throttle, boost, precision and dash, plus estimated time to the next mine based on that same live speed.
- FPP/TPP switching now blends the camera eye and focus over a short frame-rate-independent transition. At a stable mode endpoint, the renderer performs only that view's ray-clearance scan; extra candidate and blended-ray scans run only during the transition. Both candidate poses are clamped to the active tunnel/throat, the intermediate blended eye is reprojected inside its local cross-section, and the final look ray is checked again so the transition cannot cut a corner through an S-bend wall. The ship model follows the blend in and out rather than appearing/disappearing at the mode toggle.
- TPP mouse orbit keeps the spacecraft as its actual focus instead of a fixed point ahead along the course. If the direct view ray intersects a curved wall or narrow gate sleeve, the camera moves inward along the last clear segment rather than turning the view onto the obstruction. The ray clearance tapers from the eye's larger wall margin to the ship's collision-hull margin, so a valid ship position near the aperture edge does not force the camera to ignore it. FPP remains at the pilot viewpoint and clips its look ray at obstructions.
- Camera regression tests cover the focus distance used by FPP versus TPP, verify that throat-obstructed reverse rays request a camera pull-in, confirm the ship's collision-hull margin is more permissive than the camera-eye margin, and check that the FPP reticle stays aligned to the final camera ray even when that ray is shortened by a wall.
- Endless survival is now a selectable mode and the main Play action enters it directly; the live HUD names the active mode. Custom Seed and Practice launch paths set their own run identity, while Campaign remains explicitly unfinished.
- Camera aim follows mouse-look angles independently from ship yaw/pitch. In TPP, mouse-look moves the camera eye around the spacecraft while the focus stays on the ship. The camera moves closer when a wall or throat blocks the view; ray-clearance margins taper from the camera eye to the ship's collision-hull margin. FPP stays at the cockpit with a mouse-directed, tunnel-clamped look target.
- W accelerates above cruise, S brakes even when boost or precision is held, blocks new dash activations, and settles back toward cruise when released. An already-triggered dash keeps its short committed burst; regression assertions cover these priorities. Positive yaw/pitch now drive the ship in the same right/up direction the rendered nose points, with dedicated regression tests; lateral steering banks the ship smoothly into turns and returns it toward level when released, without rolling the tunnel camera.
- Obstacle generator v16 keeps the four seeded throat families (Single S, Double S, Helical Weave, Split Wave) with eased bends and adds a deliberately forgiving launch gate: lateral amplitude 1.10–1.45 units, vertical amplitude 0.14–0.28, and sampled slope ceilings 0.28 and 0.16. The 18-unit-per-side sleeve and 9-unit narrow core remain unchanged, as does the existing low-poly graphics model. The first two gates now form a learning ramp: gate #0 is a centered Wide aperture with a 35%-strength bend, while gate #1 is a mildly offset Standard aperture with a 55%-strength bend. Full seeded gate variety begins at gate #2. Hazard generator v7 keeps the first four gate encounters free of mines and places the first mine between gates #4 and #5, giving roughly 27 seconds before the first moving threat at default cruise speed. Gate planes are now 54 units apart, leaving an 18-unit recovery stretch between their 18-unit-per-side sleeves; hazard generator v7 places the first mine between gates #4 and #5, then uses alternating recovery gaps with 108-unit spacing; every mine remains 27 units from neighboring gate planes. The obstacle hash advances to v16 and the hazard hash separately records v7. Regression coverage samples both sides of the narrow core across 512 deterministic gates, checks the eased envelope, and now checks the first-gate runway. Manual in-game playability still needs verification. The renderer uses a fixed 1280×720 logical canvas with centered letterboxing for non-16:9 displays, and crash results identify inner-throat impacts separately from gate-plane collisions.
- The tunnel renderer samples 23 ring frames at 1.5-unit intervals from 15 units behind the ship to 18 ahead. Panel, seam and rail fog use band midpoints; ordinary scenery, pickups and detailed mine shells disappear by the 17-unit horizon. After playability feedback, gate rims and their opaque bulkheads were given an independent 16-to-64-unit fade, revealing the next aperture earlier while keeping far-side tunnel geometry hidden. Mine warning beacons retain their own long-range cue. The bounded tunnel-panel pass drops from 1,640 to 880 submitted triangles per frame (about 46% fewer in that pass); this is a geometry-work estimate, not a measured FPS result. Regression tests cover the separate visibility envelopes, including the early gate silhouette. Hardware profiling and in-game readability still need verification.
- The Hangar uses explicit keyboard focus: confirming Back cannot accidentally purchase/equip the selected ship. Purchase/equip is a separate focused action, and the shop layout now adapts to narrower windows.
- All eight spacecraft now use filled, ship-specific wing planforms with a defined canopy and twin engine bells instead of only thin outline silhouettes.
- Narrow gate frames have opaque bulkheads around their real apertures, preventing the rest of the next section from showing through. Six animated wall filaments follow the generated centerline and twist for a more wormhole-like continuous tunnel.
- Controls map W to accelerate, S to brake, A to steer left and B to steer right (D remains a right-steer alias), and mouse movement to camera look only. The keyboard mapping is now a pure tested helper; tests cover W/S, A/B, the D alias, opposed-key neutralisation, rotation and roll. The HUD computes a future throat-centre cue from the shared sleeve sampler, calls for pitch up/down where vertical alignment is needed, keeps tracking the current throat after its gate plane, switches to the next throat only after exiting the current one, and renders a small 3D target ring at that same sampled centre in both FPP and TPP. When a gamepad is connected, keyboard and right-stick rotation now combine instead of the stick's resting axis overriding the keyboard.
- Camera target follows the spacecraft's yaw/pitch using a target point clamped inside the sampled tunnel frame. Longitudinal target distance follows the heading, including controlled look-back.
- Six seed-selected mine presentation families are implemented: Orbital, Prism, Rotor, Cross, Halo Array, and Shard Cluster. Family names are reflected in the in-run hazard cue; these are cosmetic and do not alter the mine physics hash.
- Camera targeting and visual-family coverage have automated unit assertions.
- The Seed Lab route diagnostics use a bounded, fixed-size state graph. Its 64-state beam starts with all 36 unique aim/mode policies, then expands the eight highest-clearance parent trajectories across two aim offsets and all four control modes. This gives each selected parent eight branches instead of only one; aim offsets rotate gate by gate, and aims in a course-relative frame using current and gate centerline samples, shares gameplay's gate-crossing interpolation, applies the live swept moving-mine collision model, uses a unit-tested local avoidance projection that estimates arrival time from forward speed and checks projected craft position as well as the gate aim. Per-candidate clocks and mine-pruned counts remain visible, and surviving parents are prioritized by their weakest gate clearance using stable insertion sort on the fixed candidate array, avoiding temporary allocation. Automated tests cover every ship on a 12-gate baseline and replay deterministic diagnostics for a 32-seed × 8-ship batch. The Seed Lab also reports mine hits against collision checks and shows the search-miss reason when no witness is found. Because this graph is bounded and heuristic, Seed Lab uses WITNESS and NO WITNESS labels instead of PASS/FAIL; no witness is a search miss, not proof that no safe route exists. This remains empirical coverage, not exhaustive reachability proof.

## Update rule

After each meaningful implementation chunk, update this snapshot, the root README's progress section, `docs/ROADMAP.md`, and the main-site project page if user-visible capability or status changes. Never mark a milestone complete merely because its UI or documentation exists.


### Moving hazard motion profiles

Generator version 3 now assigns every mine one of four reproducible trajectories: lateral sweep, vertical sweep, elliptic orbit, or figure-eight. This motion channel is seeded independently from the four cosmetic shell silhouettes. The HUD shows both layers, motion profiles are included in the canonical hazard hash, and tests cover deterministic family selection and movement bounds. Collision still uses the shared spherical proxy; richer multi-part hazard choreography remains future work.


### Procedural tunnel-wall architecture

The renderer now selects one of five deterministic decorative wall motifs every 24 course units: Ribbed Metal, Plasma Rails, Fractured Panels, Spiral Conduits, or Lattice. Motifs vary panel seams, rib density, active rail lanes, and subdued palette through a rendering-only seed channel. The opaque tunnel remains continuous and continues to use the existing collision sampler; no decorative motif creates a gameplay obstacle. Coverage and deterministic repeatability are unit-tested across 512 sections.


### Procedural gate architecture variety

A visual-only gate generator now chooses between Radial Cage, Segmented Crown, Chevron Brace, Twin Rails, and Split Clamps through a seed channel independent of gate difficulty and collision data. The renderer applies each as a different annular support pattern while preserving the existing safe opening. The flight HUD reports the gameplay gate kind together with the selected structure. Automated tests check repeatability, family coverage and the minimum visual clearance; manual in-game readability still needs a separate review.


### Mine proximity warning pass

Moving mines now carry a segmented in-world warning ring in their own sampled tunnel frame. The ring starts at 54 course units, pulses faster as the craft closes in, and adds a second ring plus an urgent HUD label at 22 units. The warning uses the same animated center as the mine mesh but remains purely visual; the mine's spherical collision proxy and procedural hash are unchanged. Tests cover threshold edges, pulse bounds and determinism.


### Expanded mine silhouette library

Two new procedural mine meshes extend the existing four: Halo Array uses three intersecting hoops around a core, and Shard Cluster uses six faceted crystal fins. Palette and silhouette are chosen on the existing visual-only seed channel; movement and hitbox generation are unchanged. Automated coverage checks all six shells over 512 deterministic hazard indices. In-game readability and frame-time review still need to be performed.


- The in-run HUD now displays the selected throat waveform family (S-Bend, Double S, Helical Weave, or Split Wave) beside the course seed and steering cue. This makes the generated passage topology inspectable during flight instead of leaving the family label available only to diagnostics/tests.
